电脑体检台 v1.6.1 —— ext 扩展目录使用说明
================================================

这个目录是「加菜口子」：放进去的自定义检查/体检树/修复指南，程序启动时自动加载，
不用重新打包。内置功能一个都不会被覆盖——同名文件会被忽略并在日志里记一条告警。

目录结构
--------
ext\checks\            放自定义检查脚本（.ps1）
ext	rees\             放自定义体检树（.yaml 后缀，内容是 JSON，和内置树同格式）
ext
epairctions\    放自定义修复动作（.json）
ext\示例\              现成的三个示例文件，照着改最快

怎么加一个检查（三步）
--------------------
1. 复制 ext\示例\checks\demo_ext_check.ps1 到 ext\checks\，改个新名字（文件名=检查项 ID）。
2. 在你的体检树（下一步）里把这个 ID 写进某一层的 checks 列表。
3. 重启电脑体检台（或重开网页版），勾选你的树跑一遍。

怎么加一棵体检树
----------------
1. 复制 ext\示例	rees\演示体检.yaml 到 ext	rees\，文件名改成树的 ID（英文），
   比如「清杂质.yaml」。注意：文件内容是 JSON（合法 YAML 子集），另存时保持 UTF-8。
2. 顶层 display_name 是网页版菜单里显示的名字；layers 里每层列要跑的检查项 ID。
3. 「全面体检」按钮只跑内置五棵树；你的树在树选择器里单独选着跑。

怎么加一个修复动作
------------------
1. 复制 ext\示例
epair\demo_ext_guide.json 到 ext
epairctions\，改 id（不能和内置动作重名）。
2. level 三选一：
   green = 程序可以替用户跑（低风险、可回滚）；
   yellow = 要用户逐项确认后才跑（改设置类）；
   red   = 只显示步骤指南，程序永远不替用户执行（推荐新动作用这个，最安全）。
3. match_checks 填这个动作对应哪些检查项（问题页的「去修复」按这个连线）。

冲突规则（重要）
----------------
- 同名文件/同 ID：内置优先，你的文件被忽略；server 模式在日志记
  「ext ... ignored (conflicts with built-in)」（%TEMP%\diag-web-server-crash.log），
  命令行模式在 stderr 告警。
- 损坏的 JSON/脚本：跳过并记日志，不影响内置功能。
- ext 只做「新增」，这是刻意的安全设计。

卸载注意
--------
卸载程序时会问你 ext\ 和 reports\ 要不要保留——里面有你自己加的检查和历史报告，
默认保留。删了就找不回来了。
